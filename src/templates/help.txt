decree runs durable state-machine workflows from plain files: every run is
an append-only log that survives crashes and restarts and continues where it
stopped. It needs no AI; when a workflow uses AI, a model or a person only
picks among the options a state declares. It is built from three blocks:

  Messages  Markdown files that say what to do (the body) and which machine
            does it (`machine:` in the frontmatter). One message is one run.
  Machines  YAML statecharts in .decree/machines/ that say in what order:
            states, what each state invokes, which event leads where. They
            name scripts but contain no code and no paths.
  Scripts   Executables in .decree/machines/<name>/scripts/ that do one piece of work and
            report one outcome. Bash by default.

A model, a person or a program only ever picks among the transitions a
machine declares, in a state that invokes `model` or `reply`.

Commands:
  decree init [--ai AI] [--permissions]
                              Create .decree/, add the plugins ai, order,
                              prune and skill, and list the others; --ai
                              (claude, copilot or opencode) sets AI_CLI in
                              .env.example. claude and copilot get the skill
  decree check                Validate machines and pending messages
                              (--format sarif: a SARIF 2.1.0 log for code
                              scanning)
  decree graph                Write each machines/<name>/graph.md and system.md: Mermaid diagrams in Markdown
  decree schema               Write .decree/schema/v1/, a local copy of the
                              JSON Schemas for machines, messages, events,
                              router files and --format json output
  decree plugin list          The official plugins built into decree, marked
                              added and differs
  decree plugin add NAME... [--force]
                              Copy official plugins, and those they need,
                              into .decree/plugins/ and install them
  decree plugin export [NAME] [--dry-run]
                              Share a machine as one file: write
                              .decree/plugins/NAME.md from machines/NAME.yml
                              and scripts/NAME/; no NAME: every plugin whose
                              installed copy was edited
  decree plugin import FILE|- [--force]
                              Check a plugin, copy it to .decree/plugins/
                              and install it (curl -fsSL URL | decree plugin
                              import -)
  decree plugin install [NAME...]
                              Install new and changed plugins, keeping
                              edited copies; with NAMEs, install those over
                              any edit. Nothing else installs plugins
  decree daemon --once [--dry-run] [--quiet]
                              Start (firing @reboot cron files, so the order
                              plugin runs each machine's order/), deliver
                              replies, continue pending runs and drain inbox/,
                              printing each run's output and a status line;
                              then exit. A failed run is reported and the rest
                              run. Exits 1 if any run failed. --quiet prints
                              only notices
  decree daemon --once --retry ID [--state S]
                              First continue a failed or interrupted run
  decree daemon --once --machine M,... | --exclude-machine M,...
                              Run only these machines, or all but these
                              (also DECREE_MACHINES, DECREE_EXCLUDE_MACHINES;
                              daemon takes them too)
  decree daemon [--interval D] [--retry ID [--state S]] [--quiet]
                              The same, plus scheduled cron, every D (default
                              2s), until stopped; for unattended work, as
                              --once exits while a run waits for a reply
  decree stop [-m NOTE]       Let the runs going now finish, then hold the
                              queue: writes .decree/attention/manual-stop.md;
                              delete it to resume (Ctrl-C interrupts the run)
  decree emit [--machine M] [--param K=V]...
                              Queue a message from stdin: a body for M, or a
                              whole message (decree emit < FILE runs it
                              again). Prints its id
  decree event ID EVENT [-m NOTE]
                              Reply to a run waiting for a reply
  decree status [ID] [--all]  What needs attention, runs by status and queued
                              messages (--all lists every one), and active
                              runs in projects below; one run's events
  decree status --cron        Cron files and when each fires next
  decree tail [ID]            Follow the live output of each run as it comes,
                              or of run ID until it stops
  decree upgrade              Print how to upgrade decree (install line, pinned
                              and cargo install forms) and what to run in
                              each project after; runs nothing
  decree help                 This help text
  decree                      A short synopsis of the quick start; runs
                              nothing (run the queue with decree daemon --once)
  decree --version            Print the version

  --format json on check, status, emit, event, stop, graph, schema, upgrade,
  plugin and daemon --once --dry-run prints one JSON document instead of text, described by
  .decree/schema/v1/cli/<command>.schema.json; exit codes stay the same.

Files (.decree/):
  plugins/<name>.md           A machine's folder as one file: machine, scripts,
                              cron files, state and order seeds; committed
  machines/<name>/            One folder per machine, installed from plugins/:
    machine.yml               The machine
    scripts/                  Its scripts, and its helpers, config and data,
                              never run by decree
    cron/                     Message templates queued on a schedule
    state/                    What it keeps between runs ($DECREE_STATE_DIR),
                              declared under its `state_files:`; *.git.txt
                              committed, the rest not
    order/                    Messages run in order at each daemon start; commit
    graph.md                  Written by `decree graph`; commit it
  system.md                   Written by `decree graph`; commit it
  .env  .env.<name>           KEY=value for every script, or one machine's
                              (env_file:); gitignored but .env.example
  inbox/                      Queued messages, run in filename order
  runs/<id>/                  One folder per run: message.md, events.jsonl, logs
  schema/v1/                  Optional; written by `decree schema`, not committed.
                              Editors use the hosted copy (docs/editors.md)

Messages:
  ---
  machine: develop            # machines/develop/machine.yml; required
  params:                     # sets the machine's data for this run
    max_rounds: 3
  ---
  # Add rate limiting to /api/upload
  The body is the task. decree never changes it.

  decree adds `id` and `trigger` when it claims a message, and mirrors
  the run's `state` into runs/<id>/message.md. runs/<id>/events.jsonl is the
  record. A machine's order files, machines/<name>/order/*.md, are messages
  the order plugin runs at each daemon start, in filename order, each once
  and again when it changes; a failed one stops the ones after it.

Machines:
  # Graph: graph.md
  name: deploy
  description: Build, ask a person to approve, then ship.
  initial: build
  states:
    build:
      invoke: build               # scripts/deploy/build, else scripts/build
      transitions: { done: approval }
    approval:
      invoke:
        reply:
          question: Ship it?
          notify: notify_person
      transitions:
        approve: { target: ship, description: Ship this build. }
        reject:  { target: rejected, description: Do not ship. }
    ship:
      invoke:
        script: { name: ship, attempts: 2 }   # re-run on a non-zero exit
      transitions: { done: done }
    done:     { final: true }
    rejected: { final: true }
    failed:   { final: true }     # every machine has one; unhandled errors go here

  A machine is an SCXML statechart written in YAML. `invoke` has one key,
  which names the kind:
    <script>, or script: { name: <script>, attempts: 2, timeout: 10m }
                                              a script
    check: { visits: S, less_than: 3 }        a condition: true or false
    model: { question: ..., output: <state> } a router machine asks a model
    reply: { question: ..., notify: <script> } someone replies: `decree event`
    machine: <name>                           a child run of another machine
  Other keys: onentry and onexit (scripts run on entering or leaving a state,
  or the whole run at the root), data, emits, compound states (initial plus
  states), and final.

Scripts:
  An invoked script's event is `done` on exit 0 and `error` otherwise, unless
  it writes an event name to the file $DECREE_EVENT_FILE, as in
  echo pass > "$DECREE_EVENT_FILE". Output goes to
  runs/<id>/<NNNN>-<state>-<script>.log and is never parsed. A script queues
  more work with `decree emit`, for the machines listed in its state's `emits`.

  Environment: DECREE_PROJECT_ROOT, DECREE_MESSAGE, DECREE_MESSAGE_ID,
  DECREE_MACHINE, DECREE_STATE, DECREE_PHASE, DECREE_VISITS, DECREE_RUN_DIR,
  DECREE_MAX_DEPTH, DECREE_STATE_DIR, DECREE_ATTEMPT, DECREE_MAX_ATTEMPTS,
  DECREE_FINAL_ATTEMPT, DECREE_TRIGGER, DECREE_EVENTS, DECREE_EVENT_FILE,
  DECREE_PARENT, DECREE_RECEIVED, DECREE_DATA_<NAME>; with an attempts list DECREE_ATTEMPT_VALUE and
  DECREE_ATTEMPT_VALUES; in a router run DECREE_REQUEST and DECREE_REPLY; for a
  notify script DECREE_WAIT_ID, DECREE_QUESTION and DECREE_CHOICES; and TRACEPARENT
  (W3C Trace Context: the run's trace and the script's span), with TRACESTATE
  when the message carried one.

No configuration file; conventions, fixed limits and variables instead:
  machines/router/machine.yml     # answers every model invoke that names no router:
  attempts: 3, or [local, claude] # inside a script invoke; default 1
                                  # (no retry); a list sets DECREE_ATTEMPT_VALUE
  DECREE_MAX_DEPTH=20             # max_depth, default 10: deepest chain of emits
                                  # and child runs (shell or .decree/.env)
  script logs                     # each capped at 2 MiB
  Share a machine across projects as a plugin, .decree/plugins/NAME.md:
  decree plugin export NAME, then decree plugin import FILE elsewhere.

Cron (.decree/machines/<machine>/cron/<name>.md, run by `decree daemon`):
  ---
  cron: "0 9 * * 1-5"             # weekdays at 9:00
  machine: develop
  ---
  # The weekday morning task
  ## Overview, ## Outcome, ## Constraints, ## Acceptance Criteria

Getting started:
  1. decree init                  Set up the project
     decree plugin add develop    Add an official plugin (decree plugin list)
  2. Write .decree/machines/<name>/order/01-<what>.md (the order plugin runs it)
  3. decree check                 Validate machines and queued messages
  4. decree daemon --once         Run it; `decree status` shows what happened

More: README.md, docs/routers.md (router machines for other models) and
docs/services.md (model servers and other long-running services), at
