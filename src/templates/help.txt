decree runs durable state-machine workflows from plain files: every run is
an append-only log that survives crashes and restarts and continues where it
stopped. It needs no AI; when a workflow uses AI, a model or a person only
picks among the options a state declares. It is built from three blocks:

  Messages  Markdown files that say what to do (the body) and which machine
            does it (`machine:` in the frontmatter). One message is one run.
  Machines  YAML statecharts in .decree/machines/ that say in what order:
            states, what each state invokes, which event leads where. They
            name scripts but contain no code and no paths.
  Scripts   Executables in .decree/scripts/ that do one piece of work and
            report one outcome. Bash by default.

A model or a person only ever picks among the transitions a machine declares,
in a state that invokes `model` or `person`.

Commands:
  decree init [--ai AI] [--permissions]
                              Create .decree/ with machines, scripts and the
                              router machine for AI (claude, copilot or
                              opencode). claude and copilot also get the skill
  decree check                Validate machines and pending messages
                              (--format sarif: a SARIF 2.1.0 log for code
                              scanning)
  decree graph                Write .decree/graph/: Mermaid diagrams in Markdown
  decree schema               Write .decree/schema/v1/: JSON Schemas for
                              machines, messages, events, router files and
                              --format json output
  decree process [--dry-run]  Deliver replies, continue pending runs, drain
                              inbox/, then run pending migrations in order.
                              A failed inbox run is reported and the rest
                              run; a failed migration stops it. Exits 1 if
                              any run failed
  decree process --retry [ID] [--state S]
                              First continue a failed or interrupted run: ID,
                              or the migration blocking the queue
  decree daemon [--interval D]
                              The same passes plus cron, every D (default 2s)
  decree emit --machine M [--param K=V]...
                              Queue a message for M; the body is read from
                              stdin. Prints its id
  decree event ID EVENT [-m NOTE]
                              Reply to a run waiting for a person
  decree status [ID]          Runs by status and queued messages; one run's events
  decree status --cron        Cron files and when each fires next
  decree tail [ID]            Follow the live output of a run
  decree prune --older-than AGE [--dry-run]
                              Delete finished runs older than AGE (30d, 12h,
                              90m, 90s); --dry-run lists them
  decree help                 This help text
  decree --version            Print the version

  --format json on check, status, emit, event, prune, graph, schema and
  process --dry-run prints one JSON document instead of text, described by
  .decree/schema/v1/cli/<command>.schema.json; exit codes stay the same.

Files (.decree/):
  machines/<name>.yml         Machines
  scripts/<name>              Scripts shared by every machine
  scripts/<machine>/<name>    A machine's own scripts, found before scripts/
  migrations/  processed.md   Ordered, run-once messages and their ledger; commit both
  inbox/                      Queued messages, run in filename order
  cron/                       Message templates queued on a schedule
  runs/<id>/                  One folder per run: message.md, events.jsonl, logs
  graph/                      Written by `decree graph`; commit it
  schema/v1/                  Written by `decree schema`; commit it. Each machine's
                              first line points editors at it

Messages:
  ---
  machine: develop            # machines/develop.yml; required
  params:                     # sets the machine's data for this run
    max_rounds: 3
  ---
  # Add rate limiting to /api/upload
  The body is the task. decree never changes it.

  decree adds `id` and `trigger` when it claims a message, and mirrors
  the run's `state` into runs/<id>/message.md. runs/<id>/events.jsonl is the
  record. Migrations are never edited: each runs from a copy, once, in
  filename order, and a failed one blocks the ones after it.

Machines:
  # yaml-language-server: $schema=../schema/v1/machine.schema.json
  # Graph: ../graph/deploy.md
  name: deploy
  description: Build, ask a person to approve, then ship.
  initial: build
  states:
    build:
      invoke: build               # scripts/deploy/build, else scripts/build
      transitions: { done: approval }
    approval:
      invoke:
        person:
          question: Ship it?
          ask: ask_person
      transitions:
        approve: { target: ship, description: Ship this build. }
        reject:  { target: rejected, description: Do not ship. }
    ship:
      invoke:
        script: { name: ship, attempts: 2 }   # re-run on a non-zero exit
      transitions: { done: done }
    done:     { final: true }
    rejected: { final: true }
    failed:   { final: true }     # every machine has one; unhandled errors go here

  A machine is an SCXML statechart written in YAML. `invoke` has one key,
  which names the kind:
    <script>, or script: { name: <script>, attempts: 2, timeout: 10m }
                                              a script
    check: { visits: S, less_than: 3 }        a condition: true or false
    model: { question: ..., output: <state> } a router machine asks a model
    person: { question: ..., ask: <script> }  a person replies with `decree event`
    machine: <name>                           a child run of another machine
  Other keys: onentry and onexit (scripts run on entering or leaving a state,
  or the whole run at the root), data, emits, compound states (initial plus
  states), and final.

Scripts:
  An invoked script's event is `done` on exit 0 and `error` otherwise, unless
  it writes an event name to the file $DECREE_EVENT_FILE, as in
  echo pass > "$DECREE_EVENT_FILE". Output goes to
  runs/<id>/<NNNN>-<state>-<script>.log and is never parsed. A script queues
  more work with `decree emit`, for the machines listed in its state's `emits`.

  Environment: DECREE_PROJECT_ROOT, DECREE_MESSAGE, DECREE_MESSAGE_ID,
  DECREE_MACHINE, DECREE_STATE, DECREE_PHASE, DECREE_VISITS, DECREE_RUN_DIR,
  DECREE_STORE, DECREE_ATTEMPT, DECREE_MAX_ATTEMPTS, DECREE_FINAL_ATTEMPT,
  DECREE_TRIGGER, DECREE_EVENTS, DECREE_EVENT_FILE, DECREE_PARENT, DECREE_RECEIVED,
  DECREE_DATA_<NAME>; with an attempts list DECREE_ATTEMPT_VALUE and
  DECREE_ATTEMPT_VALUES; in a router run DECREE_REQUEST and DECREE_REPLY; for an
  ask script DECREE_WAIT_ID, DECREE_QUESTION and DECREE_CHOICES; and TRACEPARENT
  (W3C Trace Context: the run's trace and the script's span), with TRACESTATE
  when the message carried one.

No configuration file; conventions and fixed limits instead:
  machines/router.yml             # answers every model invoke that names no router:
  attempts: 3, or [local, claude] # inside a script invoke; default 1
                                  # (no retry); a list sets DECREE_ATTEMPT_VALUE
  max_depth                       # 10: deepest chain of emits and child runs
  script logs                     # each capped at 2 MiB
  Share machines or scripts across projects by symlinking them into machines/
  and scripts/.

Cron (.decree/cron/<name>.md, run by `decree daemon`):
  ---
  cron: "0 9 * * 1-5"             # weekdays at 9:00
  machine: develop
  ---
  Run the weekday morning task.

Getting started:
  1. decree init                  Set up the project
  2. Write .decree/migrations/01-<name>.md
  3. decree check                 Validate machines and pending messages
  4. decree process               Run it; `decree status` shows what happened
